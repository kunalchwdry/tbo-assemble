## Notes on intended callers

- `/api/ai/parse` (anonymous upload parsing (demo)): Needs decompression caps for XLSX/DOCX (plan section 6).
- `/api/bookings` (guest creates a booking (POST); owner lists (GET)): Creation stays public for open events; listing must become owner-only.
- `/api/bookings/[bookingId]` (booking holder (confirmation link); owner): Booking id acts as the capability today.
- `/api/events` (owner (dashboard)): GET lists every event with guests, bookings and rules; POST creates events (and a demo agent when none exists).
- `/api/events/[eventId]` (owner; booking page reads it today): GET full event; PATCH/DELETE without identity.
- `/api/events/[eventId]/feedback` (guest submits; owner reads): Submission can stay public with limits; the read side is owner-only.
- `/api/events/[eventId]/rooming-list` (owner): Export of guest names and rooms.
- `/api/events/search` (owner; booking page uses it today): Returns event ids by name, which the booking page then expands via /api/events/{id}.
- `/api/guests` (owner): GET returns every guest record (names, emails, phones).
- `/api/rfp` (owner): Supplier requests and quotes.
- `/api/v2/booking-access/exchange` (holder of a booking-link token): Exchanges a 256-bit link token for an HttpOnly session bound to one booking; same-origin, rate-limited.
- `/api/v2/booking-access/legacy` (holder of a pre-existing booking URL (temporary bridge)): Bearer booking id -> 2-hour view-only session; LEGACY_BOOKING_LINKS=0 disables it (410). Sunset planned.
- `/api/v2/public/events/[slug]` (anyone with the event link): Allowlisted public fields of active/published events only; no guests, agent, rules or ids.
- `/api/vendors` (owner): Supplier details.
