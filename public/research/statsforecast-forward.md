# Automatic StatsForecast forward research

This is a research-only experiment, not the production allocator, the current traffic estimate or the one-week flight-price predictor. Its input is **public industry-wide DGCA/Ministry of Civil Aviation scheduled domestic passenger traffic**, not TBO bookings, searches, available inventory, supplier quotes, hotel demand or fares. Do not use its outputs as a purchase recommendation.

## Schedule and archive

A GitHub Actions job in the primary `kunalchwdry/tbo-assemble` public repository is configured to run weekly on Mondays at 07:17 UTC, on changes to its research code, or by manual workflow dispatch. Runs can be delayed, skipped, disabled or fail; the website reports the last visible job and latest archive status rather than assuming success. GitHub-hosted runners for public repos are currently free subject to GitHub's terms and availability; GitHub may suspend schedules after repository inactivity. There are no new paid credentials or services. The workflow has repository `contents: write` permission solely to update the dedicated `traffic-research-history` branch; it does not write to main or use TBO, Supabase, supplier or user credentials. The archive branch is public and is configured not to trigger Vercel deployments. Its files contain only public route aggregates, forecasts and source identifiers; never place user data or credentials there.

The job pulls the existing app's public route-traffic API for all six routes. It checks route identity, source timestamp (not more than 36 hours old or over five minutes in the future against the job clock), date/quality fields, an allowlisted source manifest and its SHA-256, and no source month in or after the current month. It saves at most one capture per route per ISO week and stops at 104 captures per route, without silently deleting earlier captures. Each capture records a source manifest and a hash of the normalized complete source rows; the archive retains the full normalized input rows, source URLs and hashes, the latest 24 usable monthly outcomes, and model and frozen-selection version identifiers. A hash does not authenticate the source or prevent a repository administrator from altering both data and hash.

A previously reported source/server time of 15 November 2026 conflicted with the session date of 13 November 2026. Job and source clocks are checked against each other but **are not independently certified**. Git branch history and commit timestamps can be rewritten by repository administrators. Do not treat captured predictions as proven prospective evidence until trusted chronology is verified. The job uses a one-day minimum gap before the target and refuses to record across a month/week rollover, but this does not certify commit time.

## Future forecast and comparison

For a future month, the latest usable observation must be the previous month. Otherwise the snapshot is retained with **forecast withheld**. When eligible, the job fits actual `SimpleExponentialSmoothingOptimized` and seasonal `AutoETS` (12 months), on the same 36-month t−2 history and causal gap rules as the offline study. It also freezes last-observed and last-year baselines. It records the fixed route policy selected in the earlier retrospective study, not a new policy chosen using later results. Model errors, missing baselines, missing latest data, invalid values and a target less than 24 hours away prevent forecasting.

Only the first stored forecast per target is evaluated, against the first later archived valid source observation after the target month, when available. All four candidate methods share the same scored target months. Values may later be revised; the first retrieved result is not necessarily the official final value. The result is descriptive, likely empty for some time, and cannot establish future accuracy. Prior retrospective design choices and public-source revisions make results less independent than a preregistered trial. The existing route-policy check is separate: it records the app's current policy and its baselines in the server-side archive. No automatic comparison is itself permission to switch the live rule.

Reproduce and run tests with Python 3.13 and `pip install -r scripts/requirements-statsforecast.txt`; `python -m unittest tests/prospective_statsforecast_test.py -v`. Running `python scripts/prospective_statsforecast.py --state-dir PATH` updates a **local** isolated state directory. Never backdate or substitute a test state for the online archive.
